# v0.3 Import Evidence Agent — Architecture

**Status**: Design · **Date**: 2026-07-21 · **Branch**: `fix/v0.2.2-internal-trial-findings`

## 1. Problem

The MVP qualification scorer cannot assess import_activity, china_dependency, or
cargo_value_potential from a company website alone. These three dimensions
require customs-grade evidence. Without them, qualified prospects read as REVIEW
with `IMPORT_EVIDENCE_REQUIRED`, and a reviewer may mistake that for "weak
prospect" when it is really "weak source."

## 2. Solution

An Import Evidence Agent that fetches, normalizes, deduplicates, and scores
shipment data from multiple providers. The agent is a pipeline with clear
boundaries: each provider has its own adapter; normalization and matching are
deterministic; LLM is only used for goods-description classification and
Chinese-language summaries.

## 3. Data Source Selection

### Primary: ImportYeti
- Free tier; covers US ocean import BOL data
- Company-level search with supplier/origin breakdown
- Strength: rapid company discovery with real shipment counts
- Limitation: estimated values, limited HS granularity, US ocean only

### Secondary: Canadian Importers Database (CID)
- Government-published; observed (not estimated) values
- Covers Canadian importers missed by ImportYeti
- Limitation: annual aggregates, delayed publication

### Not Primary: USITC Dataweb
- HS-code-level trade statistics, not company-level records
- Cannot answer "does this company import?"
- Use: supplementary HS-code validation, not core evidence

### Upgrade Path: Datamyne / PIERS
- Paid; observed values; air + ocean + rail
- When: after MVP validation shows demand for premium data
- Prerequisite: commercial license review

## 4. Pipeline Architecture

```
Provider → RawRecord → NormalizedShipment → EntityMatch → EvidenceSignal
                  ↓                              ↓
           append-only                   match audit trail
```

### Stage 4A: ImportYeti + Fake
- FakeImportEvidenceProvider for tests
- ImportYetiProvider (read-only HTML parsing)
- Shipment deduplication
- Basic entity resolution

### Stage 4B: CID + Quality
- CsvImportEvidenceProvider
- Evidence quality scoring
- Cross-source consistency checks

### Stage 4C: Conflict Resolution
- Multi-source conflict detection
- Reviewer workflow for disputed evidence
- Confidence-weighted signal promotion

## 5. Data Model

### Raw Records (append-only)
- provider, provider_record_id, raw_payload_json, raw_payload_hash
- fetched_at, provider_updated_at, schema_version
- request_id for audit traceability

### Normalized Shipments
- Importer/shipper names and addresses
- Country of origin, ports, dates
- Master/House BOL, carrier SCAC, vessel/voyage
- Container numbers, weight_kg, TEU
- HS codes (raw + normalized), goods description
- Value + value_type (observed / provider_estimated / system_estimated / unknown)
- provider, provider_record_id, shipment_fingerprint

### Entity Resolution
- Strong match: same domain, same address, same provider ID, same phone/reg ID
- Composite match: normalized name + city/state/postal + domain/address
- Fuzzy: RapidFuzz token_set ≥ 92 + region match → auto_match; 80-91 → needs_review
- Store: match_method, match_score, match_reasons, review_status

### Shipment Deduplication
- Primary key: provider + provider_record_id
- Fallback fingerprint: provider + master_bol + house_bol + carrier_scac +
  arrival_date + vessel + voyage + normalized_importer + normalized_shipper +
  container_numbers + origin/destination ports
- Master/House BOL rules: House = commercial shipment; Master = parent transport;
  same Master multiple Houses ≠ merge; same House multiple container rows ≠
  multiple shipments

### Evidence Quality
- Dimensions: source_reliability (0.30), entity_match_confidence (0.25),
  freshness_score (0.20), record_completeness (0.15), cross_source_consistency (0.10)
- Grades: HIGH ≥ 0.80, MEDIUM ≥ 0.60, LOW ≥ 0.40, REVIEW < 0.40

## 6. Hard Semantic Rules
- Unknown ≠ zero
- No public record ≠ no imports
- Estimated ≠ observed
- Broker ≠ importer
- Notify party ≠ consignee
- Hidden/private records ≠ no activity

## 7. LLM Boundaries
LLM permitted for: goods description classification, HS code suggestion,
Chinese-language summary, evidence explanation.

LLM prohibited for: company merging, BOL deduplication, shipment counting,
YoY calculation, value estimation, converting "unknown" to positive evidence.

## 8. Provider Adapter Interface

```python
class ImportEvidenceProvider(Protocol):
    @property
    def provider_name(self) -> str: ...
    async def fetch(self, company: Company) -> list[RawImportRecord]: ...
    async def fetch_by_name(self, name: str, country: str | None) -> list[RawImportRecord]: ...
```
