# ADR-0026 — 安全出站抓取策略

状态：**已批准（设计），阶段 1 实施**（v0.2，分支 `feat/v0.2-research-agent`）
日期：2026-07-19
相关：ADR-0025（官网研究边界）

## 背景

v0.2 让服务端去抓取由用户提供的 URL。这正是典型的 SSRF 场景：攻击者控制目标，
而我们的服务器拥有他们没有的网络位置 —— 回环服务、内网网段，以及像
`169.254.169.254` 这样可能返回凭据的云元数据端点。

除 SSRF 外，不受控的抓取器还会：被无限响应耗尽内存、在死主机上挂起、无限跟随
重定向、或对第三方站点造成骚扰级别的压力。

这些都无法事后补救，必须是抓取器围绕其构建的策略。

## 决策

### 1. 每次请求前校验，包括每一次重定向之后

只校验用户输入的 URL 是标准绕过点：一个被允许的主机可以 302 到 `127.0.0.1`。

guard 是对 `(url, resolved_ips)` 的**纯函数**，拒绝以下情况：

1. 协议不是 `http` / `https` —— 拒绝 `file:`、`ftp:`、`gopher:`、`data:`、
   `javascript:`；
2. URL 内嵌凭据（`http://user:pass@host`）；
3. 主机解析出的**任意**地址属于 loopback、私网、link-local、unique-local、
   多播、保留或未指定 —— 覆盖 `127.0.0.0/8`、`10/8`、`172.16/12`、
   `192.168/16`、`::1`、`fc00::/7` 与 `169.254.0.0/16` 元数据网段。必须
   **全部**地址通过，而不是第一个通过即可；
4. 主机名命中 `localhost`、`*.localhost`、`*.internal`、
   `metadata.google.internal`；
5. 端口不是 80 或 443；
6. 重定向超过 3 跳，或任意一跳离开同站范围。

### 2. 同站范围基于用户输入的原始主机，不猜测可注册主域名

允许 `host == origin`、`host` 是 `origin` 的子域，以及 origin 的 www / 非 www
对应形式。**按标签比较，不做字符串后缀比较** —— 否则 `notexample.com` 会被判
为匹配 `example.com`。

有意不引入公共后缀列表（PSL）依赖：从 `www.example.co.uk` 取末两段会得到
`co.uk`，进而放行整个 `*.co.uk`，这是严重的过宽。本策略比 PSL 方案更严格，
代价是少数多域名企业会被漏掉 —— 这个方向的错误可以接受。

### 3. 资源限制是配置项，不是抓取循环里的字面量

每次运行 5 页；单页传输 2 MB（流式截断）；解压后 8 MB（防 zip bomb）；清洗后
保留 40,000 字符；单请求超时 10 秒；**单次运行总预算 45 秒**；单主机并发 2；
请求间隔 500 ms。

超出总预算不是错误，而是返回 `partial`。

### 4. 礼貌与合规

每次运行抓取一次 `robots.txt` 并缓存，严格遵守我们 UA 对应的规则。
`robots.txt` 抓取失败按"允许"处理（标准行为）；若 `robots.txt` 禁止首页，则
整次运行中止并给出明确信息。User-Agent 诚实标识机器人身份并附联系 URL。

### 5. 留存策略

不持久化第三方网页全文。只保存 URL、抓取元数据（状态码、content type、字节数、
字符数、时间戳、截断标记）以及被引用为证据的短片段。

### 6. 测试只能通过显式注入放宽 guard

集成测试在回环地址上提供 fixture 页面，而第 3 条禁止回环。测试通过构造函数
注入替代 guard，而不是削弱生产默认值。**不存在任何可以在部署环境中关闭 SSRF
防护的环境变量或开关。**

## 备选方案

**只校验一次用户 URL，然后让 `httpx` 自动跟随重定向。** 最简单，且错误 ——
重定向链正是绕过点。

**只用主机名黑名单。** 攻击者用自己的域名配一条指向 `127.0.0.1` 的 A 记录即可
绕过。解析后的 IP 级判定是必需的。

**通过只允许公网 IP 的出口代理转发抓取。** 确实更强，也是生产规模下的正确答案。
v0.2 拒绝，因为它是项目目前还不具备的部署基础设施；待离开单机 Docker Compose
后再引入。

## 后果

**好处。** 危险面被收敛成一个小的纯函数，整个攻击矩阵可用表驱动单元测试完整
覆盖且不需要网络。限制是配置，调参不触碰抓取循环。留存策略让我们不至于大规模
存储抓取到的第三方内容。

**代价。** 遵守 `robots.txt` 意味着部分合法潜客无法被研究 —— 这是正确的，但会
偶尔让用户困惑。同站策略比 PSL 更严格，会漏掉少数多域名企业。

**如实记录的残留风险。** DNS 重绑定存在残留窗口：校验发生在解析之后、连接之前。
彻底消除需要把连接绑定到已校验 IP（涉及 SNI 与证书校验的复杂处理）或走出口
代理。阶段 1 采用"连接前校验 + 连接后对端地址核对"，把窗口压到最小并如实记录；
生产级方案见备选方案第三条。
